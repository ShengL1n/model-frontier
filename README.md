# 模型观测台 · Model Atlas

本地 React + Ant Design + ECharts 三榜融合工作台。直接读取 Artificial Analysis、Vals、LiveBench 的公开数据，自动发现模型，重点展示开放权重模型，不维护模型关注白名单。

## 三榜融合功能

- **综合总览**：全球与开放权重领先模型、全量模型覆盖分布和各站同步状态。默认进入总览。
- **融合排行榜**：综合能力评分与成本披露分离，没有成本的模型仍可参与排名；可搜索、按厂商和开放状态筛选、按分数排序，并导出当前筛选结果。可打开「LiveBench 能力维度」列按编程、推理、研究等分类原始分排序（仅 LiveBench 提供维度，缺失保持空白）；融合总榜下方固定展示「覆盖口径差异」面板，并排对照严格口径与探索口径的名次与前沿成员变化。
- **单榜模型库**：在排行榜内切换 AA、Vals、LiveBench，保留各站全部配置，按原始总分排名。默认排除历史 / 估算配置，可分别启用；有分无成本仍排名。原始总分无效的配置保留但不赋名次。
- **模型对比**：从融合榜勾选或从详情、搜索添加 2–4 个模型。展示三榜排名分、原始分、每站任务成本、配置、AA token 价格与速度 / 延迟，以及 LiveBench 分类原始分；选择保存在本机。
- **预算约束筛选**：在评分口径面板选择某一来源并设定每次任务美元成本上限，超预算模型与未披露该来源成本的模型从列表和前沿图中隐藏；只改变显示，不改变分数、名次与前沿。综合相对成本继续用于跨源观察，不充当美元预算。
- **前沿探索与权重敏感性**：保留既有二维帕累托、独立开放权重前沿和完整样本场景验证。图中以最便宜的前沿模型为锚点渲染「被支配区」，区域内模型同时成本更高、综合分更低；区域随「全球前沿」图例显隐。
- **数据来源与刷新**：三站后台 HTTP 定时抓取、失败回退、来源日期及原始配置追溯。

排行榜、对比与前沿共享评分预设、权重、最低覆盖、估算开关；通过“调整评分口径”进入排行榜设置。排名分由同一综合样本计算。显示筛选不改变分数和已有名次；单榜原始分不直接跨榜相加。单榜视图的历史 / 估算配置开关仅控制该单榜视图，不影响综合评分。

支持 `#overview`、`#rankings`、`#compare`、`#explore`、`#stability`、`#sources` 页面地址，刷新后保持所在页面。「复制分享链接」把当前权重、覆盖门槛、估算与质量排除开关、成本口径、预算筛选、排行榜筛选和对比选择写入页面锚点参数（如 `#rankings?p=equal&ms=3`），打开同一链接即在完全相同口径下复核结论；默认值不写入链接。「导出 CSV」与「导出当前榜单」均附带数据时间与完整评分口径列，单榜导出另附该来源的获取时间与版本标签，便于日后复核同一结论。页面顶部“导出 CSV”导出综合快照（前沿页应用该页显示筛选）；排行榜内“导出当前榜单”导出当前源与筛选结果。

## 使用

当前机器上已安装依赖、构建完毕。双击 **启动模型前沿.command**，浏览器打开 <http://localhost:4317>。若已经运行，会复用现有服务。

普通终端方式（在本目录）：

```sh
npm ci
npm run build
npm start
```

需要 Node.js >= 22.12 和网络。仅监听 127.0.0.1。网页资产已本地打包，运行时不从 CDN 下载组件。

- `npm run dev`：开发模式，同样使用 4317 端口，与生产模式二选一。
- `npm run refresh`：独立执行三站抓取并写入缓存；不要与正在运行的服务同时执行。日常使用网页“从源站刷新”即可。
- `npm test`：解析器、模型身份、排名、前沿、缺失处理、缓存回退与并发刷新测试。
- `npm run test:portal`：六页导航、单榜切换、筛选导出、对比持久化和移动布局的端到端验证。使用本机无头 Chrome，仅供测试。
- `npm run test:e2e`：服务运行后检查桌面/手机布局、预设、详情、导出、错误提示和设置接口。使用本机 Chrome。

## 自动更新

默认本地服务运行期间每 6 小时刷新，可在网页改为每小时、每天或关闭。启动时缓存到期会补更。无需 API key 或 Codex 会话。已有刷新间隔设置会保留。

Arena 已移除：不再采集或参与评分，启动时清理旧快照中的该来源，页面迁移旧权重。这里使用三站的公开网页数据，并非承诺存在统一官方 API。

三站均通过后台 HTTP 读取公开页面、内嵌结构化数据和 CSV。运行和定时刷新不依赖浏览器，不会启动 Chrome；源站拒绝时保留最后成功缓存并显示原因。服务关闭或电脑休眠时不继续刷新，下次运行补更。

数据目录可用 `FRONTIER_DATA_DIR` 覆盖，端口可用 `PORT` 覆盖（双击启动器固定 4317）。

`data/snapshot.json` 保存源站原始配置行、成功获取时间、最近尝试时间、错误、发布标签和刷新间隔。单站失败独立回退；少于 5 条的异常响应不替换缓存。手动刷新与自动刷新共享执行锁，同进程内不会重复抓取。

## 权重与计算

默认“能力优先”：**AA 40%、Vals 35%、LiveBench 25%**。该比例是可调整的分析判断，不是被验证的最优权重，不按网站访问量估计权威性。

另有“三榜等权”“任务实践优先”“广覆盖双榜”。后者使用 AA 60% + LiveBench 40%，用于扩大双榜覆盖，不能当作三榜结论。权重敏感性页对照三种完整覆盖口径，并提供前沿稳定性指数：固定同一批三榜分数与三源成本均完整的模型，在 3 套能力权重 × 4 种成本口径（综合指数、AA、Vals、LiveBench）共 12 场景统计前沿入选率。分别报告全球与开放权重前沿；未进入固定样本的模型不记为零。该频率不是最优概率或统计置信度，也不替代二维前沿。

默认至少 2 榜，以保留更多新模型及开放权重模型。覆盖度只作证据信息展示，不参与能力评分；已删除覆盖加分及实验开关。不将覆盖率称为统计可信概率。

严格模式仍可选：对全部启用榜单都有有效分数的模型构成共同基准样本。各榜按原始分数降序排名，并列取平均名次：

`排名分数 = 100 × (N − r) / (N − 1)`

再按权重加权，只有一个模型时记 50。关闭 AA 估算分开关时，估算分不参与评分。搜索、厂商和开放权重显示筛选不改变基准分数及已计算的前沿。

探索模式：允许不完整榜单覆盖，各榜按有效样本排名，模型缺失榜单不补零，对已有权重重新分配。这使不同模型的比较依据不同，界面明确提示，分数旁的信息图标标明部分覆盖，只用于发现候选。融合排行榜的「覆盖口径差异」面板同时计算两种口径的结果：严格口径（全部启用榜单）与探索口径（至少 X 榜），直接列出仅在探索口径可评分的模型、名次变化与前沿成员身份变化。无论当前处于哪种口径都给出双向对照；差异来自比较样本与权重再分配，不代表模型能力变化。

默认横轴是 **综合相对成本（基准 1 倍）**：对三站成本都有效、为正且估算设置允许的固定模型样本，分别求 AA、Vals、LiveBench 任务成本中位数；模型各站成本除以对应中位数，取三个比值的等权几何平均并乘 100。公式为 `100 × ∛[(AA/AA中位数) × (Vals/Vals中位数) × (LB/LB中位数)]`。完整三源时，成本权重各 1/3，与能力权重独立。默认允许至少两源成本：缺一源时对两个有效比值取平方根，等权几何平均，标记 2/3；完整时标记 3/3。中位数基准始终用三源完整样本计算。页面展示值为原指数除以 100，例如 10.1 显示为基准的 0.10 倍，不是美元，不可解读为生产账单；缺失不补值，少于两源不入图。部分覆盖仍有任务分布偏差，显示覆盖数量不能消除这种不确定性。中位数与每站明细在模型详情可复算。切换单站成本时，才使用该站的 **每次任务美元成本**。不将三个来源美元成本直接相加。成本缺失、为零或非正不入对数图。LiveBench 的任务成本使用可用类别的总 cost / 总 tasks；详情单榜核对也显示它的每次成功任务成本，两者有明确标记。

帕累托：不存在另一模型成本不高、分数不低，且至少一项更优，则属于前沿。分别计算全体模型的全球前沿，以及只在开放权重模型中计算的开放前沿。图中连线只引导视线，不表示模型之间可连续插值。

**为什么不同口径下的前沿不同？** 成本来源、推理档位、发布版本和样本交集会改变结果。模型详情展示支配者、综合成本和三种美元成本下的前沿结果，以及单榜完整样本核对，便于定位差异。

## 模型身份与开放状态

自动归并采用名称语法去除明确的 inference effort 后缀，保留日期、Preview、Vision 等版本区分；少量明确品牌名称映射用于 Wonder / Muse Wonder 1.0。没有模型准入白名单。未知的新模型也加入并集。无法确认的名称分别保留，因此模型条目总数不等于基础架构的独立数量。

每站代表配置优先选择非估算、非历史条目，然后取最高有效分数；同分时使用已披露的较低任务成本。成本与该条配置绑定，不能将高档位能力配上低档位成本。模型详情保留该站全部配置。

开放权重来源为 AA `isOpenWeights`和 LiveBench `openweight`。只依据源站披露，不以中国厂商或模型名字猜测。信息冲突时标记“来源有分歧”，未披露为“未确认”。**开放权重不等于 OSI 认可的开源，也不自动意味着允许任何商用用途**；许可证显示在模型详情。

## 已知边界

- 模型族归并不是统一实验：各站的 effort、工具、测试时间和 fallback 可能不同。部分 Anthropic 分数包含 fallback。
- 用排名舍弃了原始分差。综合分不是正确率，不给出虚假的综合置信区间。
- 历史 AA 配置保留在发现列表，详情有标记；单榜核对剔除 AA 历史和估算配置。缺失任一榜单的模型仍可在表中找到。
- API 任务成本不能替代本地推理的硬件、显存、吞吐、能源或运维成本。
- 源站页面、Next.js 内嵌字段、CSV 路径或名称规则改变时，适配器可能需要维护。解析失败明确报错，不会静默编造数据。

## 文件结构

- `server/adapters.mjs`：三站真实采集及解析。
- `server/identity.mjs`：模型名称归并与开放状态证据。
- `server/store.mjs`：快照、失败回退、刷新锁和间隔判断。
- `server/index.mjs`：本地 HTTP 服务和自动更新。
- `src/analysis.mjs`：综合评分、前沿与单榜核对；可独立测试。
- `src/main.jsx`：统一导航、评分设置、状态与详情。
- `src/Portal.jsx`：总览、融合 / 单榜排行榜和模型对比。
- `src/portal.mjs`：排序、筛选、单榜配置、预算约束、覆盖统计与安全导出。
- `src/share.mjs`：分享链接参数与页面口径状态的编解码。
- `src/CompareChart.jsx`：三榜排名分柱状对比。
- `src/Chart.jsx`：ECharts 图表、SVG 图标工具栏与滚轮事件边界。
- `src/presentation.mjs`：相对成本倍数与真实美元价格格式。
- `data/snapshot.json`：随交付附带的本次真实数据快照，之后由程序更新。

## 图表交互与显示

界面统一使用 Ant Design 组件与 `@ant-design/icons` 的 SVG 图标。图表滚轮 / 触控板缩放已关闭，滚轮用于页面滚动。拖动图表平移横轴，缩放通过按钮和滑块完成，可重置、全屏和下载 PNG。悬浮卡同时列出三站真实美元任务成本，下方基准卡显示各站中位数；成本倍数表示相对基准，并非真实统一账单。

## 仓库治理

小型分析页，治理从简，文档全部面向「下一棒读者」：

- `AGENTS.md`：AI 协作命令速查、改动后验证流程与已知坑。
- `CONSTITUTION.md`：不可妥协原则（诚实性红线、显示与评分分离、架构不漂移）。
- `NORTH_STAR.md`：北极星——结论可被任何人在同一口径下复核；附反指标。
- `ROADMAP.md`：已交付 / 点名才做 / 明确不做，不维护愿望清单。
- `docs/adr/`：架构决策记录（单服务不换栈、分享链接契约、量化口径基准、门禁选型）。
- `openspec/`：轻量规格约定，沉淀分享链接与融合评分两项核心契约。

质量门禁：ESLint（`--max-warnings 0`）、Stylelint、Prettier、单测覆盖率阈值（行 92% / 分支 85% / 函数 90%）。CI（GitHub Actions）只跑静态检查 + 带阈值的单测 + 构建；三套 E2E 依赖本机 Chrome，留作发布前人工必跑（`docs/adr/0004`）。
