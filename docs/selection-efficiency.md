# 选型效率与结论复核

范围：能力维度探索、预算约束筛选、可分享可复现的比较、覆盖口径差异展示。前三项高优先级改进（配置差异摘要、真实变化快照、质量提示与主动排除）已在 `docs/evidence-and-history.md` 一轮交付，本轮不重复。

验收约定：
- 能力维度只使用 LiveBench 已有分类原始分；AA 与 Vals 无对应维度，缺失保持空白，不外推为综合能力。按维度排序只改变显示顺序，不改变综合分与名次。
- 预算筛选按单一来源的真实美元任务成本隐藏超预算模型；未披露该来源成本的模型一并隐藏。只改变显示范围，不改变分数、名次与前沿；综合相对成本不充当美元预算。
- 分享链接编码权重、覆盖门槛、估算与质量排除、成本口径、预算、排行榜筛选和对比选择；默认值不入链。仅在应用初始化时解码一次，应用内 hash 导航不做参数回放。URL 含 `?` 即为分享链接：缺省口径字段一律取默认值（初始化与粘贴恢复用同一谓词 `location.hash.includes('?')` 判定，保证同一链接在任何机器复现同一结论）；无 `?` 的地址不视为分享链接，沿用本地偏好；对比选择是本机数据，仅在链接显式带 `sel` 时覆盖。
- 导出附带数据时间与完整评分口径；单榜导出另附该来源获取时间与版本标签。数据时间取快照的 lastRefresh，不是导出时刻。
- 覆盖口径差异面板无论当前口径如何，都并排给出严格口径（全部启用榜单）与探索口径的对照；名次与前沿差异来自样本与权重再分配，不表述为能力变化。

## 关键实现位置

- `src/share.mjs`：链接参数编解码；非法枚举与越界数值一律丢弃，`ms` 钳位到 1–3。
- `src/portal.mjs`：`applyBudget` / `budgetSummary` / `livebenchSuiteKeys`。
- `src/analysis.mjs`：`scopeComparison`（严格 vs 探索的双向对照）；`csvExport(rows, meta)` 附加「数据时间」「评分口径」列；`nativeCsvExport` 附加「获取时间」「源站版本」列。
- `src/Portal.jsx`：排行榜的提升状态（`ranking` 对象）、维度列开关、预算提示、口径差异面板。
- `src/main.jsx`：预算控件、URL 与状态实时同步（`history.replaceState`，不产生历史记录）、复制分享链接、排行榜筛选状态提升（跨标签页保持）。

## 本轮顺带修复的既有缺陷

- `server/history.mjs` 的 `load` 只校验顶层结构，「合法 JSON 但嵌套 rows 损坏」的文件会被接纳并在后续访问崩溃；现逐层校验 `sources.*.rows`，损坏文件保留原样并明确报错（对应基线中唯一失败的单测）。
- `src/HistoryDrawer.jsx` 的重置 effect 缺 `open` 守卫，关闭抽屉瞬间内容被清成空状态（滑出动画中肉眼可见）；现仅在打开时重置。该缺陷也是 evidence-e2e 第 17 步严格模式歧义失败的根因。
- `server/history.mjs` 的 `capture` 现在在「哈希变化但行与版本标签均无差异」时跳过归档，避免字段顺序演化这类不可观察差异产生「0 条变化」记录；随本次修复清除了 data/history.json 中已存在的一条此类噪声记录。
- 测试选择器：排行榜新增口径差异表格后，主表格使用 `ranking-main-table` 类名，portal-e2e 横向滚动断言随之更新。

## 独立审查后的修正

- `scopeComparison` 的并列综合分此前会从名次表遗漏（症状：面板出现「第 undefined 名」、并列模型被误报为仅探索口径可评分），已改为与 `rankedModels` 同口径。
- 同文档打开分享链接（仅 hash 变化、页面不重载）此前会被状态同步覆盖回写；现在外部 hash 变化带参数时按链接恢复口径，应用内导航用 ref 标记跳过。对比选择仅在链接显式带 `sel` 时覆盖，与 reload 语义一致。
- 分享编码：无有效上限的预算来源不编码（原先会把 null 钳位成 `bl=0.000001`）；自定义权重保留 6 位有效数字，不再取整；`sel` 单个 id 截断 120 字符。
- 复制分享链接按当前状态即时构造，不再读去抖后的地址栏；URL 同步做 250ms 去抖，避免输入期间触发浏览器 replaceState 限流。
- `budgetSource` / `budgetLimit` 现随本地偏好跨会话恢复；`minSources` 在初始化与链接恢复两处按当前权重非零源数收敛；预算成本读取锁定 `representatives[source].costTask`，删除顶层兜底避免跨源归因。

## 复审修正（对上一节修正后的代码再次全覆盖审查）

- 分享链接口径语义在初始化与同文档粘贴恢复两条路径上曾不一致：reload 对缺省字段回落本地偏好，粘贴则取默认值，同一链接在同一机器可能复现出不同结论。现两条路径以同一谓词（URL 是否含 `?`）判定分享链接，带 `?` 即整链为完整口径状态；仅含无效参数的链接两条路径行为也一致。
- 排行榜筛选的粘贴恢复曾被 `state.view` 门控：缺省 `v=` 的链接不回到融合视图，且 250ms 状态同步会把本地值写回链接（链接静默膨胀）。现缺省即恢复融合视图。
- `server/history.mjs` 的 load 校验补齐 rows 元素级：`rows:[null]` 这类合法 JSON 可绕过校验，在服务启动时于 `diffSnapshots` 抛 TypeError 退出（`loadState` 的 `history.load` 调用在 try 之外）。现损坏文件一律走「保留原文件 + 明确报错」。
- 两条 CSV 导出对非法时间戳会抛 RangeError（本地缓存可被手工编辑）；现解析失败留空。
- `decodeShareState` 只在第一个 `?` 处切分页面与参数（此前 `#rankings?q=a?b&ms=3` 会丢 `ms`）；`scopeComparison` 行查找改为 Map 索引。
- 预算提示口径统一为「未披露或不可核对该来源成本」（成本为 0 的模型同样会被隐藏）；预算来源被质量排除整表隐藏时，排行榜明确提示原因，提示谓词与 `applyEvidencePolicy` 的整源排除分支逐字同源（前置条件为「排除过期 / 失败缓存」开关开启）。

## 验收结果

单元测试 75/75 通过（含 share 编解码边界、预算筛选、口径差异、导出元信息、并列名次与损坏历史文件回归）。`npm run build` 通过。`npm run test:portal`、`npm run test:evidence`、`npm run test:e2e` 全部通过；portal 套件覆盖能力维度列、口径差异面板、预算筛选、分享链接复制与复原（含同文档 hash 导航、「缺省字段一律默认值，不回落本地偏好」断言）。全覆盖审查经三轮迭代（初评 10 条 → 修复 → 复核抓出 2 条残留 → 修复 → 终审通过）后无可检出缺陷终止。桌面与 375px 窄屏无横向溢出，图表滚轮行为不变。
