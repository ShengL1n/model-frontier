# ADR-0008：LiveBench 摄取改用双形态发布枚举与多布局探测

- 状态：已接受
- 日期：2026-10-19
- 决策人：owner（会话报告「livebench 抓取失败，选更稳健的方案」→ 实测后选定）

## 背景

2026-10-19 定时刷新起 LiveBench 抓取失败，报「发布文件未找到；保留上次数据」。与
AA 在 ADR-0006 那次同一性质：入口页面与 JS 均正常获取（HTTP 200），失败发生在发布
文件定位，即摄取契约失效，而非网络波动。

实测（2026-10-19）站点变化：

- 入口 JS（`/static/js/main.<hash>.js`）内的 releases 列表形如：

  ```js
  const _e = ["20261014"];
  const Me = (e) => `${e.slice(0, 4)}-${e.slice(4, 6)}-${e.slice(6, 8)}`;
  const Oe = [
    ...["2024-06-24", …, "2026-06-25"].map((e) => ({ id: e, label: e, gen: "v1" })),
    ..._e.map((e) => ({ id: e, label: Me(e), gen: "v2" })),
  ];
  ```

- 发布 id 分两种形态：**v1 代是虚线日期**（`2026-06-25`），**v2 代是紧凑日期**
  （`20261014`，标签「2026-10-14」）。当前最新发布是 v2 的 2026-10-14。
- 数据文件布局随代际不同：v1 在 `/v1/table_<YYYY_MM_DD>.csv`（已从改版前的根目录
  迁入子目录），v2 在 `/data/<紧凑id>/table.csv`；cost 文件同布局（`cost_<日期>.csv`
  / `cost.csv`）。另有 `categories.json` / `breakdown.json`，本项目不摄取。
- 旧实现扫 JS 里的虚线日期、只拼根路径 `table_<日期>.csv`：v1 文件已迁走（根路径
  全部 404），v2 的紧凑 id 压根不出现在虚线日期扫描里——两头落空。
- 站点对未命中路径有两种响应：缺失文件返回 404，无扩展名路径返回 SPA 壳
  （HTTP 200 + HTML）——200 不等于拿到数据。

## 决策

`fetchLivebench` 改为「枚举候选发布 → 按布局探测 → 表头校验」：

1. **双形态 id 枚举**：从入口 JS 提取所有带引号的虚线日期与紧凑日期（`20\d{6}`），
   按归一化日期排序（新→旧），取前 12 个作为候选发布。候选来自站点自己的 bundle，
   不再从任意日期字面量里猜。
2. **多布局探测**：每个候选按「现行布局 → 历史布局」依次尝试 `[table, cost]` 布局
   对：虚线 id 试 `/v1/` → 根目录 → `/data/<id>/`；紧凑 id 试 `/data/<id>/` → `/v1/`
   （由紧凑 id 派生虚线日期拼文件名）→ 根目录。任一布局重新启用或回迁都能接住。
3. **表头校验拦网**：候选响应必须以 `model,` 开头才算命中；cost 文件同样校验，
   拿到 SPA 壳按缺失处理（成本为 null），不把解析垃圾当数据。
4. **失败分级**：入口 JS 里找不到任何发布 id → 「发布列表未找到」（JS 结构变化）；
   有 id 但全部布局落空 → 「发布文件未找到」（布局变化或网络）。两者均保留上次缓存，
   不静默少数据。

口径不变（ADR-0003）：score 仍为可用 suite 等权均值。新表头为 7 个 suite
（long_agentic / reasoning / coding / browser / data_analysis / research / design），
无 overall 列，与既有计算一致；成本仍取每次任务成本，不与每次成功任务成本混用。

## 后果

- 正常路径 1 次请求即命中最新发布（v2 布局首发命中）；站点再改版时通常只需给
  `lbLayouts` 加一项布局，编排逻辑不动。
- 最坏情况（全部布局落空）最多 12 × 3 = 36 次探测，单次 12 秒超时；仅在站点整体
  故障时发生，且终点是明确报错而非脏数据。
- 候选里可能混入与发布无关的日期字面量（如模型发布笔记日期），多一次 404 探测，
  无正确性影响。
- 编排层此前零测试覆盖（坏了只能等定时刷新报错才发现）；本次补 6 个用例：v2 命中、
  v2→v1 回退、根目录旧布局兜底、SPA 壳拦截、cost 壳按缺失处理、三级失败报错。
- 已知遗留：`categories.json` / `breakdown.json` 未摄取；若将来要按类目加权（改变
  口径），需先修订 ADR-0003 并另立规格。

## 实施中发现的坑（2026-10-19 记录）

- **200 不等于数据**：站点对无扩展名路径返回 SPA 壳（`/v1/` 实测 200 + HTML）。旧
  代码只校验了 table 的表头、没校验 cost——cost 拿到 HTML 壳会被 csv-parse 解析出
  垃圾列。现在两处都校验。
- **v2 id 是紧凑日期**：`"20261014"` 不带横线，任何按 `20\d{2}-\d{2}-\d{2}` 扫描的
  旧逻辑都对它隐形；两种形态都要枚举。
- **发布很稀疏**：v1 最新是 2026-06-25，v2 唯一发布 2026-10-14；拿「今天附近的日期」
  去试（如 10-16 / 10-17）必然 404，候选必须来自 bundle 里的列表。
