# ADR-0004：质量门禁选型与 CI 范围

- 状态：已接受（CI 范围部分已由 ADR-0014 取代）
- 日期：2026-10-16

## 背景

项目很小，门禁要能防回归，但不能把维护成本抬得比项目本身还高。E2E 依赖 Playwright 驱动的本机 Chrome。

## 决策

- **ESLint**（扁平配置）+ `eslint-plugin-react-hooks`（含 set-state-in-effect / refs 等新规则），`--max-warnings 0`；JSX 变量使用用 `react/jsx-uses-vars` 兜底，不引入完整的 eslint-plugin-react 风格规则集。
- **Stylelint** `stylelint-config-standard`；豁免 `no-descending-specificity` 与 `no-duplicate-selectors`——分区追加式 CSS 的级联顺序承载视觉行为，强制重排的回归风险大于收益。
- **Prettier** 默认风格，全量格式化，`data/` 与 lock 文件豁免。
- **覆盖率门禁**：node:test 原生覆盖率，行 92% / 分支 85% / 函数 90%（基线 94.07 / 87.59 / 93.78）。
- **CI（GitHub Actions）只跑**：lint、format:check、带阈值的单测、构建。三套 E2E 留在本地（依赖本机 Chrome 与 4317 端口，进 CI 的收益抵不过环境漂移的折腾；若未来要进，再修订本 ADR）。

## 后果

- CI 分钟数极低（无浏览器下载），门禁全绿即单测与静态检查可信。
- E2E 仍是人工发布前的必跑项，见 `AGENTS.md` 验证流程。

## 后续修订

- ADR-0007 曾把 CI 改为「实时刷新数据 + 三套 E2E」；ADR-0014 现将其定为「确定性夹具 E2E + 独立源站巡检」。本 ADR 中「三套 E2E 留在本地」的描述只代表 2026-10-16 的决策，不再表示现状。
